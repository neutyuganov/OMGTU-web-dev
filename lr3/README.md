# Лабораторная работа 3 — Форма обратной связи с валидацией и состояниями в React

Запуск:
```
npm install
npm run dev
```

## Контрольные вопросы

**1. Чем управляемый компонент отличается от неуправляемого? В каких случаях useRef предпочтительнее useState для поля формы?**
У управляемого (controlled) компонента значение хранится в state React: `value={name}` + `onChange={...}`. Каждый ввод символа обновляет состояние, а состояние определяет, что показано в поле. У неуправляемого значение хранит сам DOM, а React читает его только когда нужно — через `useRef` (`ref.current.value`).
`useRef` удобнее, когда значение не нужно на каждом нажатии клавиши: простая форма, где данные читаются только при отправке; `<input type="file">` (его значение нельзя задать через state); интеграция со сторонними библиотеками; когда нужно избежать лишних перерисовок в большой форме.

**2. Зачем нужно состояние touched? Что изменится, если убрать его и показывать ошибки сразу при вводе?**
`touched` отмечает, что пользователь уже побывал в поле и ушёл из него (blur). До этого ошибки не показываются — это снижает раздражение пользователя. Без `touched` ошибки «Имя обязательно», «Некорректный формат email» появлялись бы с первого символа, пока человек ещё не закончил ввод, а после рендера всей формы — сразу у всех пустых полей.

**3. Почему в setErrors и setTouched используется функциональная форма prev => ...? В каких случаях можно обойтись прямым значением?**
Функциональная форма получает гарантированно актуальное предыдущее состояние. Обновления state асинхронны и группируются, поэтому если взять значение из замыкания, можно затереть другие поля объекта. Паттерн `prev => ({ ...prev, [field]: ... })` копирует все поля (spread) и меняет только одно — состояние не мутируется.
Прямым значением можно обойтись, когда новое состояние не зависит от старого и задаётся целиком — например, `setTouched({ name: true, email: true, message: true })` в `handleSubmit` или сброс `setErrors({ name: null, email: null, message: null })`.

**4. Как работает e.preventDefault() в обработчике onSubmit? Что произойдёт без него?**
Отменяет стандартное поведение браузера при отправке формы. Без него браузер отправит форму (GET-запрос на текущий адрес) и перезагрузит страницу: состояние React сбросится, валидация и имитация отправки не отработают.

**5. Какие состояния полей реализованы в CSS и как они визуально различаются? Предложите альтернативные визуальные подсказки.**
- покой (`.field__input`) — серая рамка `#d0d5dd`, светло-серый фон;
- фокус (`:focus`) — синяя рамка и мягкое синее свечение через `box-shadow`, белый фон;
- ошибка (`.field__input--error`) — красная рамка, розоватый фон, под полем красный текст ошибки;
- успех (`.field__input--valid`) — зелёная рамка, светло-зелёный фон.

Альтернативы: иконки внутри поля (✓ / ✕ / !), лёгкая анимация «встряхивания» поля при ошибке, плавное появление текста ошибки, счётчик символов, подсказка-tooltip, иконка загрузки (спиннер) на кнопке при отправке.
